# 災害写真マップ（仮称）1.0.0 仕様書（Codex 向け）

災害時に職員・消防団員がスマホで被害箇所の写真と位置を投稿し、管理画面の地図に写真が付箋のように並ぶ仕組み。
構成：GitHub Pages（`docs/` の静的ページ）＋ Google Apps Script（`gas/Code.gs`、スプレッドシートに紐づくウェブアプリ）＋ Google ドライブ（写真）＋ スプレッドシート（記録・設定）＋ Leaflet（地図）。
使う人は非エンジニアの自治体職員と消防団員（中高年も多い）。画面の文言・コメント・エラー文はすべて日本語。

## 0. 全体の決まり（必ず守る）

- 外部の npm パッケージ・CDN は使わない。地図部品は同梱済みの `docs/vendor/`（Leaflet 1.9.4・Leaflet.markercluster 1.5.3・qrcode-generator 2.0.4）だけを使う。vendor の中身は変更しない。
- それ以外（EXIF読み取り・画像縮小・ZIP作成・CSV/GeoJSON/KML・QR描画・PNGアイコン作成）は自作。Node のテストも Node 24 の標準機能だけ（node:test, node:assert, node:vm, node:http, node:zlib, node:crypto, fetch, WebSocket）。
- 秘密（合言葉・パスワード）をコード・README・手引き・コミットに一切書かない。試験では mock の中で自動生成した値を使う。
- ファイル名をアンダースコア `_` で始めない（GitHub Pages の Jekyll 対策。`_作業用` は公開しないので例外）。
- HTML に onclick などのイベント属性・インラインの `<script>` を書かない（CSP で禁止する）。イベントは JS の addEventListener。
- 利用者が入力した文字（コメント・名前・所属・メモ・災害名・区分名・目印名など）は、画面に出すとき必ず `textContent` で入れる。`innerHTML` に利用者の文字を入れない。Leaflet の DivIcon・ふきだし（popup）・ツールチップにも HTMLElement を渡し、文字列の HTML を組み立てない。
- 文字コードは UTF-8（BOMなし）、改行は LF。JS は ES2020 まで（iOS 15 Safari で動くこと）。
- **docs の自作 JS は ES モジュールにしない**。通常の `<script>`（defer）で、各ファイルを即時関数 `(function (root) { … })(typeof window !== 'undefined' ? window : globalThis);` で書き、`root.SPM.<名前>` に載せる（`root.SPM = root.SPM || {}`）。こうすると管理画面を PC のフォルダから直接（file://）開いても動き、Node の vm でも読める。読み込み順は HTML に書く（vendor → config.js → util.js → … → 画面の本体）。
- DOM を使わない計算だけのファイル（util.js・exif.js・coords.js・zip.js・export.js）は `window`・`document` に触らない（Node の vm に空の root を渡して試験する）。DOM を作る小さな部品（`el(tag, attrs, children)` など）は dom.js に分ける。
- 版番号：GAS `APP_VERSION = '1.0.0'`、`docs/config.js` の `expectedGasVersion: '1.0.0'`、`docs/sw.js` の `CACHE_VERSION = 'spm-1.0.0'`。
- Codex の作業場所の決まり：ブラウザ（Edge）は起動しない。テストのファイルは書くが流さない（流すのは Claude）。各段階の確認は `node tools/check-syntax.mjs`（構文）と、DOM のいらない小さな関数の `node -e` での1回の動作確認まで。Python は使わない。ネットにはつながない（部品はすでに docs/vendor にある）。

## 2. GAS（gas/Code.gs）

スプレッドシートに紐づくスクリプト（コンテナバインド）。ウェブアプリとして「次のユーザーとして実行：自分」「アクセスできるユーザー：全員」で公開される。利用者は Code.gs の中身を GAS エディタの「コード.gs」に丸ごと貼る。1ファイルにまとめる。冒頭に、日本語で「このファイルは何か・貼り方・直したら『デプロイを管理→編集→新しいバージョン』で公開し直す」を短く書く。

- **トップレベルには `function` と `var` だけを置く**（const・let をトップレベルに置かない。Node の vm から値を読めるようにするため。関数の中では const・let を使ってよい）。内部の関数は名前の末尾に `_` を付ける。
- **ファイルの1行目付近に `var APP_VERSION = '1.0.0';`、最後の行に `var SPM_CODE_END = '1.0.0';`** を置く。`codeComplete_()` は「SPM_CODE_END が定義されていて APP_VERSION と同じ」なら true。ping・login の応答に `codeComplete` を入れる（貼り付けが途中で切れていたら管理画面で分かる）。

### 2-1 定数・スクリプトプロパティ

```
var APP_VERSION = '1.0.0';
var TZ = 'Asia/Tokyo';
var PROP = {
  POST_CODE:   '投稿の合言葉',
  ADMIN_PASS:  '管理画面のパスワード',
  ACCEPT:      '投稿の受付',                    // 「受付中」か「停止中」
  ROOT_FOLDER: '（変更しない）写真フォルダID',
  CURRENT:     '（変更しない）受付中の災害ID',
  REV:         '（変更しない）更新番号',
  SALT:        '（変更しない）通行証の種'
};
```
- 「投稿の受付」の読み取りはゆるく：`受付中・はい・する・on・true・1・yes・open`（全角半角・大文字小文字を問わない。NFKC で正規化して比べる）を受付中、それ以外は停止中。書くときは必ず「受付中」「停止中」。
- **合言葉の正規化** `normCode_(s)`：NFKC（全角→半角）→ 空白と、ハイフンの仲間（- ‐ ‑ ‒ – — ― − ー ｰ）をすべて除く → 英字は小文字にそろえる。**パスワードの正規化** `normPass_(s)`：NFKC → 前後の空白を除く（大文字と小文字は区別する）。比べるときは保存値と入力の両方を正規化して比べる（全角数字や「4821-7306」の区切りで入れても通る）。端末側（util.js の `normCode`）も同じ規則にし、`tests/fixtures/codes.json` の例で両方を試す。
- 自動生成：合言葉＝数字8桁（文字列。全部同じ数字・12345678 のような続き番号・前と同じ値は作り直す）。**画面やダイアログでは「4821-7306」と4桁ずつ区切って見せる**（保存は区切りなしの8桁）。パスワード＝英大文字小文字と数字の12文字（0 O 1 l I を除く）。乱数は `Utilities.getUuid()` を何回かつないで SHA-256 にかけた値から作り、数字にするときは 250 未満のバイトだけを使う（偏りを防ぐ）。Math.random は使わない。
- 手入力の合言葉：正規化した後で 4〜32 文字の英数字。パスワード：8〜64 文字。
- プロパティの読み込みは `getProperties()` を1回の処理で多くて1回。設定一式（プロパティ＋設定シート＋受付中の災害の情報）を `CacheService.getScriptCache()` のキー `spm:cfg` に JSON で60秒置く。メニュー・管理画面・API で設定を変えたら必ず `spm:cfg` を消す。

### 2-3 ドライブ

- 最初の設定で、マイドライブに「災害写真マップ_写真」フォルダを作り、ID を `PROP.ROOT_FOLDER` に入れる（既にあれば作らない）。

- 写真のファイル名：`No0012-1_20270701-1432_冠水・浸水_山田.jpg`（受付番号4桁-何枚目_撮影または受付の日時_区分_投稿者）。使えない文字 `\ / : * ? " < > |` と空白は `_` に、80字まで。
- 共有の設定は変えない（非公開のまま）。

### 2-4 通行証・ロック・上限（CacheService のキーは `spm:` で始める）

- 投稿の通行証 = `base64EncodeWebSafe(computeHmacSha256Signature('post|' + 受付中の災害ID, 合言葉 + '|' + 種))` の末尾の `=` を除いたもの。合言葉か受付中の災害が変わると自動で無効になる。
- 管理の通行証 = 同じ作り方で `'admin|' + yyyyMMdd（今日・東京）`、鍵は `パスワード + '|' + 種`。照合は今日と昨日の2つ（約1〜2日で切れる）。
- 種（SALT）は最初の設定で UUID 2つをつないで作る。メニューの「ロックを解除」では変えない。
- 合言葉の誤り：`spm:fail:post` に {回数, 最初の時刻} を置き、10分の窓で30回に達したら `spm:lock:post` に解除時刻（15分後）を置く。ロック中の hello は合言葉が正しくても `locked`（あと何分）を返す。**通行証での upload / resolve はロックの影響を受けない。**ロックの発生は「記録」へ。
- 管理パスワードも同じ仕組みで `spm:fail:admin` / `spm:lock:admin`（別勘定）。
- 受付の上限：`spm:up:<10分区切りの番号>` の数が設定の上限以上なら `limit`。災害の写真枚数（災害一覧 J 列）が上限以上でも `limit`。超えたら「記録」に1回書く（同じ区切りで何度も書かない）。
- 停止中の hello / upload は、合言葉・通行証の検査より先に `closed` を返す（停止中は総当たりもできない）。

### 2-5 受け口（API）

- `doPost(e)`：`JSON.parse(e.postData.contents)` の `a` で分岐。全体を try/catch で包み、想定外の失敗は `{ok:false, error:'server', message:'サーバーで問題が起きました。少し待ってからやり直してください。'}`（中身は「記録」に短く。秘密は書かない）。
- `doGet(e)`：`e.parameter.a === 'ping'` なら ping、それ以外は `{ok:true, app:'spm', message:'災害写真マップの受け口です'}`。
- 応答はすべて `ContentService.createTextOutput(JSON.stringify(obj)).setMimeType(ContentService.MimeType.JSON)`。
- エラーの種類（error）：`closed`（受付停止中）／`code`（合言葉の誤り・通行証が古い）／`locked`（しばらく確認を止めている。`retryMinutes` つき）／`auth`（管理のパスワードの誤り・通行証が古い）／`bad`（入力の誤り。`message` に何が悪いか）／`limit`（上限）／`busy`（ロックが取れない。端末はやり直す）／`notfound`／`server`。どのエラーにも日本語の `message` を付ける。

| a | 入力 | 返すもの |
|---|---|---|
| ping（GET） | — | `{ok, app:'spm', version, codeComplete, accepting, codeKind:'digits'|'text'}`（災害名は返さない） |
| hello | `code` | `{ok, token, version, disaster:{id,name,kind}, categories:[{name,color}], landmarks:[{name,lat,lng}], map:{lat,lng,zoom}|null, backupFormUrl, limits:{maxPerPost:20}}` |
| upload | `token, id, pid, n, of, lat, lng, acc, src, shot, cat, urgent, note, who, org, ua, img, thumb` | `{ok, id, no, dup}` |
| resolve | `token, url` | `{ok, lat, lng}` か `notfound` |
| login | `pass` | `{ok, token, version, settings, disasters}` |
| state | `token`（管理） | `{ok, version, settings, disasters}`（login からパスワードの確認を除いたもの。スプレッドシートのメニューなど外で変わった受付の状態・合言葉・災害一覧を取り直すため） |
| list | `token, d, since` | `{ok, rev, disaster, items:[…], thumbs:{id:base64}, serverTime}` |
| photo | `token, d, id` | `{ok, mime:'image/jpeg', b64, name}` |
| update | `token, d, pid, patch` | `{ok, rev, items:[…]}` |
| config | `token, op, …` | `{ok, settings, disasters, newCode?}` |

**upload の検査と流れ**
1. 停止中なら closed。通行証が違えば code。
2. 検査：`id`・`pid` は UUID の形。`n`・`of` は 1〜50 の整数で n≤of。`src` は gps/exif/map/gmap/landmark/none。`src` が none のときだけ `lat`・`lng` は null（シートは空）、それ以外は `lat` −90〜90・`lng` −180〜180 の有限の数（小数6桁に丸める）。`acc` は 0以上の数か null。`shot` は40字まで。`cat` が区分の一覧に無ければ「その他」。`urgent` は真偽。`note` 500字・`who`/`org` 40字で切る。`img` は base64 で 8,000,000 字まで、デコードした先頭が FF D8（JPEG）。`thumb` は 60,000 字まで・先頭 FF D8。違えば bad。
3. 上限（2-4）を超えていれば limit。
4. 二重の確認1：キャッシュ `spm:id:<id>` か、その災害の投稿シートの F 列を TextFinder（セル全体一致）で探す。あれば `{ok, id, no, dup:true}`。
5. ドライブに仮の名前（`<id>.jpg`）で写真を保存（**ロックの外**）。
6. `LockService.getScriptLock().waitLock(20000)`（取れなければ busy。作った写真はごみ箱へ）。ロックの中で：二重の確認2（あれば作った写真をごみ箱へ入れて dup を返す）／受付番号を決める（同じ pid の行があればその番号。キャッシュ `spm:pid:<d>:<pid>`→無ければ G 列を TextFinder→無ければ災害一覧 H 列を+1）／更新番号を+1（プロパティ `PROP.REV` に書き、キャッシュ `spm:rev` にも置く）／投稿シートとサムネシートに追記／災害一覧の投稿数（新しい番号のとき+1）・写真枚数（+1）を更新。ロックを外す。
7. 写真の名前を正式な名前に直す。キャッシュ `spm:id:<id>` に `{no}` を6時間置く。`{ok, id, no, dup:false}`。

**resolve**：通行証を確かめる。URL のホストが `maps.app.goo.gl`・`goo.gl`・`google.com`・`www.google.com`・`maps.google.com`・`google.co.jp`・`www.google.co.jp`・`maps.google.co.jp` 以外なら bad。短いリンク（maps.app.goo.gl・goo.gl）は `UrlFetchApp.fetch(url, {followRedirects:false, muteHttpExceptions:true})` の Location をたどる（最大4回、毎回ホストを確かめる）。たどり着いた URL から緯度経度を読む（読み方は 3-6 の coords.js と同じ規則を GAS 側にも書く）。

**login**：ロック中なら locked。パスワードが違えば失敗を数えて auth。合えば `settings`＝`{accepting, postCode, codeKind, codeComplete, current:{id,name,kind,state,start}|null, rootFolderUrl, currentFolderUrl, categories, landmarks, map, limits:{per10min, perDisaster}, pollSeconds, backupFormUrl, postPageUrl, webAppUrl, locks:{post:{until, recentFailures}, admin:{…}}}`（webAppUrl は `ScriptApp.getService().getUrl()`、取れなければ空）と `disasters`＝災害一覧の全行（新しい順。`{id,kind,name,start,end,state,posts,photos}`）。

**list**：管理の通行証。`d` の災害が無ければ notfound。今の更新番号（キャッシュ→無ければプロパティ）が `since` 以下なら**シートを読まずに** `{ok, rev, items:[], thumbs:{}}`。そうでなければ投稿シートを読み、`rev > since` の行だけ（since=0 なら全部）を返す。サムネは返す行の分だけ（サムネシートを1回読む）。`disaster` は災害一覧のその行。

**photo**：写真IDで行を探し、ファイルを読んで base64 で返す。

**update**：`patch` に入れてよいのは `status`（4つのどれか）・`memo`（1000字）・`lat`/`lng`（両方そろって有効なとき。位置を直したら位置の取り方を「管理者が修正」にし、元の緯度・経度が空なら直す前の値を入れる。位置なしの写真に置いた場合も同じ）・`cat`（一覧にあるもの）・`urgent`・`hidden`。ロックの中で、その災害の投稿シートの pid が同じ全行を書き換え、更新番号+1、更新日時を入れる。変更後の行を返す。

**config**（管理の通行証が要る。どれも「記録」へ。成功したら `spm:cfg` を消す）
- `op:'start', kind:'災害'|'訓練', name` … 新しい災害・訓練を始める（2-6 の startDisaster_）。`newCode` を返す。
- `op:'resume'` … 受付中の災害で受付を再開（受付中の災害が無ければ bad）。
- `op:'stop', changeCode:true|false` … 受付停止。changeCode なら合言葉を自動で作り直し `newCode` を返す。
- `op:'code', code?` … code があれば手入力の合言葉（検査）、無ければ自動生成。`newCode` を返す。
- `op:'rename', d, name` … 災害名を直す（フォルダ名はそのまま）。
- `op:'mapHome', lat, lng, zoom` … 設定シートの地図の初期位置（`lat, lng` の形の文字）と拡大を書く。
- `op:'unlock'` … 投稿のロックと失敗の数を消す（管理のロックはメニューだけで消す）。
- `op:'postPageUrl', url` … 設定シート H8 に投稿ページの URL を書く（https で始まり 300 字まで）。login の settings に `postPageUrl` として返す。
- 管理画面のパスワードの変更は config では**できない**（メニューだけ）。

### 2-6 中心の処理（メニューと config で共通に使う）

`setup_()`／`startDisaster_(kind, name, from)`／`resumeAccepting_(from)`／`stopAccepting_(changeCode, from)`／`setPostCode_(codeOrNull, from)`／`setAdminPass_(passOrNull, from)`／`renameDisaster_(id, name, from)`／`setMapHome_(lat, lng, zoom, from)`／`unlock_(from)`
- `setup_()`：何度呼んでも壊れない。無いものだけ作る：写真フォルダ・「災害一覧」「設定」「記録」シート（見出しと既定値）・種・合言葉・パスワード（無ければ自動生成）・「投稿の受付」（無ければ「停止中」）・更新番号（無ければ0）。作ったものと今の合言葉・パスワードを返す。
- `startDisaster_`：受付中の災害があれば状態を「終了」・終了日時を入れる。新しい災害IDを決め、災害一覧に1行（状態 受付中）、投稿シート・サムネシート（隠す）・フォルダを作り、`PROP.CURRENT` を新しいIDに、「投稿の受付」を「受付中」に、合言葉を自動で作り直す。名前は1〜40字（空なら bad）。
- `stopAccepting_`：「投稿の受付」を「停止中」、災害一覧の状態を「停止中」。
- `resumeAccepting_`：「受付中」に戻し、状態も「受付中」。
- いずれもロックの中で行い、終わったら `spm:cfg` を消す。

### 2-7 スプレッドシートの専用メニュー

`onOpen()` で「災害写真マップ」メニュー：
①最初の設定 ②受付を始める ③受付を止める ④投稿の合言葉を変える ⑤管理画面のパスワードを変える ⑥いまの設定を見る ⑦ロックを解除

- 対話は `HtmlService.createHtmlOutput()` で作る小さなダイアログ（`SpreadsheetApp.getUi().showModalDialog`）。大きな文字・大きなボタン。HTML に入れる値はすべて HTML の特殊文字を置き換える（合言葉に < & などがあっても壊れない）。ダイアログのボタンは `google.script.run` でサーバーの関数（`dlgStart(kind,name)`・`dlgResume()`・`dlgStop(changeCode)`・`dlgCode(code)`・`dlgAdminPass(pass)`・`dlgUnlock()`）を呼び、結果を同じダイアログに出す。
- 合言葉を見せるときは「4821-7306」の区切りと、読み上げ方（0 ゼロ・1 イチ・2 ニ・3 サン・4 ヨン・5 ゴ・6 ロク・7 ナナ・8 ハチ・9 キュウ。例「ヨン ハチ ニ イチ、ナナ サン ゼロ ロク」）を添える（無線・電話で伝えるため）。管理画面の設定でも同じ。
- ①：setup_ を呼ぶ。初回だけ「地図の中心（役場などの位置で Googleマップを長押しすると出る数字を貼ってください。空でもかまいません）」を聞き、読めれば設定シートに書く。合言葉・パスワード（大きな文字）と「次にすること」（デプロイ→新しいデプロイ→ウェブアプリ、次のユーザーとして実行：自分、アクセスできるユーザー：全員→出たURLを config.js に）を出す。すでに設定済みなら「設定済みです」と今の状態。
- ②：「新しい災害」「訓練」「同じ災害で受付を再開」の3つの大きなボタン。新しい災害・訓練は名前の入力欄を出してから始める。始めたら新しい合言葉を大きく出す。
- ③：「合言葉も変えて止める（おすすめ）」「合言葉はそのままで止める」。
- ④：「自動で新しくする」「自分で決める（入力）」。
- ⑤：「自動で新しくする」「自分で決める（入力）」。変えたら新しいパスワードを大きく出し、「管理画面に入り直してください」。
- ⑥：受付の状態、受付中の災害（名前・種別・開始）、合言葉（大きく）、ウェブアプリのURL（取れれば）、版。
- ⑦：投稿・管理のロックと失敗の数を消す。

## 3. 画面の共通部分

### 3-1 config.js（通常の script）

```js
window.SPM_CONFIG = {
  appName: '災害写真マップ',
  gasUrl: '',                    // 公開した GAS のウェブアプリの URL（…/exec）を貼る
  expectedGasVersion: '1.0.0',
  defaultMap: { lat: 36.2, lng: 138.25, zoom: 5 },   // 設定シートに初期位置が無いときだけ使う
  tiles: {
    osm:    'https://tile.openstreetmap.org/{z}/{x}/{y}.png',
    photo:  'https://cyberjapandata.gsi.go.jp/xyz/seamlessphoto/{z}/{x}/{y}.jpg',
    gsiStd: 'https://cyberjapandata.gsi.go.jp/xyz/std/{z}/{x}/{y}.png'
  }
};
```
- `gasUrl` が空のときは、どちらの画面も「設定が済んでいません（config.js に GAS の URL を入れてください）」と出して止まる。
- 予備の窓口（LoGoフォームなど）の URL は設定シート（H7）に入れ、hello・login で受け取る。空でなければ、投稿ページの「受付停止中」「送れなかった」の案内に「うまくいかないときは予備の窓口から送れます」とリンクを出す。
- 試験用の差し替え：`location.hostname` が `localhost` か `127.0.0.1` のときだけ、URL の `?api=<URL>` を `gasUrl` の代わりに使う（sessionStorage `spm-api` に覚える）。管理画面は `?poll=<秒>` で自動更新の間隔も差し替えられる（同じく localhost のときだけ）。

### 3-2 見た目（見やすさ・使いやすさ最優先。和の飾りは不要）

- 白地 `#ffffff` に濃い文字 `#1a1a1a`（補足の文字は `#4a4a4a` 以上の濃さ）。パネルの地 `#f3f5f8`、線 `#c9ced6`。
- 操作の色は1色：濃い青 `#0b57d0`（白文字）。押した感じ・フォーカスの枠（3px の濃い青の外枠）をはっきり。
- 意味の色：赤 `#c62828`＝至急・失敗、黄 `#ffd54f`（黒い文字）＝送信待ち・停止中・過去の災害を表示中、緑 `#2e7d32`＝送れた・対応済。**色だけで伝えず、必ず文字・記号（✓ ! ⏳ など）も添える。**
- 状況の色：未確認＝赤の枠と「未確認」、確認済＝青、対応中＝橙 `#b45309`、対応済＝緑。
- 文字：`system-ui, -apple-system, "Hiragino Sans", "Yu Gothic UI", "Meiryo", sans-serif`。スマホの本文 17px 以上、入力欄 16px 以上（iPhone で入力時に拡大されない）、ボタンの文字 18px 太字。PC の本文 15px 以上。細い字は使わない。
- 押す所は高さ 48px 以上（スマホの主ボタンは 56px）、角丸 12px、間隔 8px 以上。
- 主な文字と背景の明るさの差（コントラスト比）は 4.5 以上（大きい文字でも 3 以上）。
- 動きは控えめ（新着の波紋・付箋が貼られる動き程度）。

### 3-3 CSP と meta（index.html・admin.html・help.html の head に入れる）

index.html・help.html：
```
default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';
img-src 'self' data: blob: https://tile.openstreetmap.org https://cyberjapandata.gsi.go.jp;
connect-src 'self' https://script.google.com https://script.googleusercontent.com;
worker-src 'self'; manifest-src 'self'; base-uri 'self'; form-action 'none'; object-src 'none'
```
admin.html：上と同じだが、script-src・style-src・img-src に `file:` を足し（PC のフォルダから直接開いても動くように）、worker-src・manifest-src は書かない。
- どのページにも `<meta name="robots" content="noindex,nofollow">`。
- Referer を止める設定（`<meta name="referrer" content="no-referrer">` など）は**入れない**（OpenStreetMap の利用方針）。

### 3-4 api.js

- `api(action, payload = {}, {timeoutMs})`：`fetch(gasUrl, {method:'POST', body: JSON.stringify({a: action, ...payload}), redirect:'follow', credentials:'omit', cache:'no-store'})`。**headers は付けない**（文字列の本文は text/plain 扱いになり、事前確認の通信が起きない）。AbortController で時間切れ（upload 120秒、そのほか 30秒）。
- 通信できない・時間切れ → `{ok:false, error:'network', message:'通信できませんでした'}`。JSON でない応答 → `{ok:false, error:'server', …}`。
- `ping()`：`fetch(gasUrl + '?a=ping', {cache:'no-store'})`。
- 例外を投げず、いつも `{ok, …}` の形で返す。

### 3-5 mapbase.js（投稿・管理で共通の地図）

- `createMap(el, {lat, lng, zoom, mobile})`：`L.map(el, {closePopupOnClick:false, zoomControl:true})`。ふきだしを開いた直後0.7秒のタップは無視して閉じる（iPhone 対策）。
- **地図は minZoom 9・maxZoom 19**（町の範囲を見る用途。ズーム8以下は地理院タイルに長い追加の出典表示が要るため使わない）。
- 下地は3つ（L.control.layers は使わず、下の🗺️パネルで切り替える）：
  - **標準地図（OpenStreetMap）**＝既定。`L.tileLayer(tiles.osm, {minZoom:9, maxZoom:19, attribution:'&copy; <a href="https://www.openstreetmap.org/copyright">OpenStreetMap</a> contributors'})`。URL に `{s}` を使わない。
  - **航空写真**＝ズーム13以下は OpenStreetMap、**ズーム14以上で地理院の全国最新写真**に切り替わる重ね（`L.layerGroup([OSM（maxZoom:13 の別インスタンス）, L.tileLayer(tiles.photo, {minZoom:14, maxNativeZoom:18, maxZoom:19})])`）。出典は OSM に加えて `<a href="https://maps.gsi.go.jp/development/ichiran.html">地理院タイル</a>（全国最新写真）`。ズーム13以下で航空写真を選んでいる間は、地図の上に小さく「拡大すると航空写真になります」。（全国最新写真のズーム13以下は海外の衛星画像で長い英文の出典が要るので使わない。ズーム14以上で GRUS 画像を含むのは沖ノ鳥島付近だけだが、念のため出典に「GRUS画像（© Axelspace）」も添える。）
  - **地理院地図（予備）**＝`tiles.gsiStd`（minZoom 9, maxNativeZoom 18, maxZoom 19、出典 `<a href="https://maps.gsi.go.jp/development/ichiran.html">地理院タイル</a>`）。OpenStreetMap が出ないとき用。
  - 航空写真・予備は選んだときに初めて読み込み、`bringToBack()`。出典の表示は常に見える位置（右下）から消さない。
- 地図の左上に、縮尺（＋−）の下へ「丸い現在地ボタン」と「🗺️ 地図の種類ボタン」。🗺️を押すと、✓つきの一覧（標準地図／航空写真／地理院地図（予備））が開く。選んだ下地は localStorage `spm-base` に覚える。
- 現在地：青い点（白い縁）と、ゆっくり脈打つ半透明の精度の円。
- スマホでふきだし・詳細を開いている間は、地図の操作ボタンを隠す（重なって読みにくいため）。
- **地図画像の先読み・保存はしない**（`keepBuffer` などを既定より大きくしない。Service Worker でも保存しない）。

### 3-6 util.js・coords.js・exif.js・zip.js・export.js（DOM なし。Node の vm で試験する。それぞれ `SPM.util`・`SPM.coords`・`SPM.exif`・`SPM.zip`・`SPM.exporter` に載せる）

- util.js：`uuid()`（`crypto.randomUUID` が無ければ `getRandomValues` で作る）、`formatJst(date)`→`yyyy/MM/dd HH:mm:ss`、`toHalfWidth(s)`（NFKC）、`normCode(s)`（2-1 の合言葉の正規化と同じ規則）、`formatCode(s)`（8桁の数字なら「4821-7306」）、`readCode(s)`（読み上げ方）、`clampText(s, n)`、`deviceKind(ua)`→iPhone/Android/PC/その他、`distanceMeters()`、`safeFileName(s, max)`。
- dom.js（DOM あり）：`el(tag, attrs, children)`（文字は必ず textContent）、`clear(node)`、`toast(msg)`、`banner(kind, msg)` など画面の小さな部品。
- coords.js：`parseLocationText(text)` →
  - `{lat, lng, kind:'coords'}`：`37.0412, 136.7790`／`37.0412 136.7790`／`37.0412,136.7790`／全角数字・全角カンマ・「北緯37.0412 東経136.7790」／度分秒 `37°02'28.4"N 136°46'44.4"E`（S・W は負）／`N37.0412 E136.7790`。
  - `{lat, lng, kind:'url'}`：Google マップの長い URL から。読む順：`!3d<lat>!4d<lng>` → `@<lat>,<lng>` → `?q=`・`&query=`・`ll=`・`center=`・`destination=` の `<lat>,<lng>`（`+` や空白・`%2C` を許す）→ `/search/<lat>,+<lng>` → `/place/<lat>,<lng>`。
  - `{needsResolve:true, url}`：`maps.app.goo.gl/…`・`goo.gl/maps/…` の短いリンク（GAS の resolve に頼む）。
  - それ以外は `null`。緯度 −90〜90・経度 −180〜180 の外は `null`。
- exif.js：`readExif(arrayBufferOrUint8Array)` → `{lat, lng, takenAt, orientation}`（無い値は null）。JPEG の APP1 `Exif\0\0` の TIFF を読む（II・MM 両方）。IFD0 → ExifIFD（0x8769）の DateTimeOriginal（0x9003。`yyyy:MM:dd HH:mm:ss` → `yyyy/MM/dd HH:mm:ss`）、GPS IFD（0x8825）の 1〜4（緯度の N/S・度分秒の有理数3つ・経度の E/W・同）。壊れたデータで例外を投げず null を返す。範囲外の読み取りをしない。
- zip.js：`makeZip(entries)`（`entries=[{name, data:Uint8Array, date:Date}]`）→ `Uint8Array`。無圧縮（store）、CRC32、ファイル名は UTF-8 で汎用フラグのビット11を立てる、DOS の日時。中央ディレクトリと終わりの記録まで正しく書く（Windows のエクスプローラーで開ける）。
- export.js：
  - `toCsv(posts, photosByPost)` → 文字列（先頭に BOM `\uFEFF`、改行 CRLF）。列：受付番号, 何枚目, 受付日時, 撮影日時, 区分, 至急, 状況, 緯度, 経度, 位置の精度(m), 位置の取り方, コメント, 投稿者, 所属, 対応メモ, 非表示, 写真ID, Googleマップ。1行＝写真1枚。値に `, " 改行` があれば `"` で囲み `"` は2つに。**先頭が `= + - @` または タブ・CR の値は先頭に `'` を付ける**。
  - `toGeoJson(posts)` → FeatureCollection（1投稿＝1 Feature、Point [lng,lat]、properties に受付番号・区分・至急・状況・受付日時・投稿者・所属・コメント・対応メモ・写真の数・写真ID）。
  - `toKml(posts, categories)` → KML 2.2。区分ごとの Style（KML の色は aabbggrr）、1投稿＝1 Placemark（name「No.12 冠水・浸水」、description に本文、ExtendedData）。XML の特殊文字 `& < > " '` は必ず置き換える。
  - `googleMapsUrl(lat, lng)` → `https://www.google.com/maps/search/?api=1&query=<lat>,<lng>`（無料の URL 形式）。

## 4. 投稿ページ（docs/index.html・post.js・post.css）

スマホで、中高年でも迷わないこと。**1画面に1つの操作**。いまどの段階かを上に出す（例「① 写真 → ② 場所 → ③ 送る」）。スマホの戻るボタン（Android）で1つ前の画面に戻れる（history.pushState / popstate）。写真を縮めて保存している間にページを閉じようとしたら確認（送信待ちに入った後は確認しない。写真は端末に残る）。

### 4-1 起動

1. `#k=<合言葉>` があれば読み取り（URL デコード・NFKC）、localStorage に保存し、`history.replaceState` で `#` 以降をアドレス欄から消す。**起動のときだけでなく、ページを開いたまま `#k=` 付きのリンクを開いたとき（hashchange）も同じように読み取り**、新しい合言葉で hello をやり直して設定（災害名など）・前の受付の下書きや送信待ちの扱いを更新し、ホームへ戻す。
2. LINE などアプリの中のブラウザ（UA に ` Line/`・`FBAN`・`FBAV`・`Instagram`）なら、上に目立つ案内「アプリの中では写真の保存などがうまく動かないことがあります。『ブラウザで開き直す』を押してください」と、「ブラウザで開き直す」ボタン（`index.html?openExternalBrowser=1`。合言葉を覚えていれば `#k=<合言葉>` も付ける。外のブラウザは記憶が別のため）。
3. `ping` で受付状態を見る（通信できなければ前回の設定〔localStorage `spm-post-settings`〕で続け、写真は送信待ちに入れられるようにする）。
4. 合言葉があれば `hello` で通行証と設定（災害名・区分・目印・地図の初期位置）を取り直す。`code` が返ったら合言葉の画面へ（「合言葉が変わりました。新しい合言葉を入れてください」）。`closed` なら黄色の帯「いまは投稿の受付をしていません」。
5. Service Worker を登録（`sw.js`、scope `./`。https か localhost のときだけ）。`navigator.storage.persist()` を頼む（使えれば）。
6. 下書き（4-3）があれば戻し、「前の続きがあります」と出す。送信待ちがあれば再送を始める。

### 4-2 画面

- **合言葉の画面**：合言葉（`ping` の codeKind が digits なら `inputmode="numeric"`）、名前・所属（任意・前回の値）。「始める」。誤りは赤い文字で「合言葉が違います」。locked は「しばらく確認できません（あと約n分）」。
- **ホーム**：上に災害名。大きな2つのボタン「📷 いまいる場所で送る（現地）」「🗂 あとから場所を決めて送る（まとめて）」。その下に「⏳ 送信待ち n件」（n>0 なら黄色で目立つ）「📝 送った記録」「❓ 使い方」（help.html）。下の方に「名前・所属を変える」「合言葉を入れ直す」。
- **現地**：
  - 「📷 撮る」（`<input type="file" accept="image/*" capture="environment">`）と「🖼 写真を選ぶ」（`multiple`）。追加した写真は小さな一覧（✕で外せる）。1回の投稿は20枚まで。
  - 画面を開いたら現在地を測り続ける（watchPosition、enableHighAccuracy）。「現在地：精度 ±12m」を表示し、小さな地図にピン。ピンは GPS に付いて動き、指で動かしたら「手で直した位置」として止める（「現在地に戻す」ボタン）。精度が 100m より悪いときは「位置が不正確です。地図で直してください」。位置が取れないときは「地図で場所を決める」へ。
  - 区分（色の点＋文字の大きなボタン。1つ選ぶ）、「至急（人命・通行止めなど）」の切替（赤・はっきり）、コメント（任意。例文「道路が30cmほど冠水、通行止めが必要」、「キーボードのマイクで声でも入力できます」）。
  - 「送信する（n枚）」。この投稿の写真は全部同じ場所・同じまとまりID。位置の取り方は gps（手で直したら map）。
- **まとめて**：
  - 「🖼 写真を選ぶ（何枚でも）」→ 1枚ずつのカード（写真・撮影時刻〔EXIF。無ければファイルの日時〕・場所の状態）。
  - 場所の状態：「📍 写真の位置情報」（EXIF に GPS があれば自動で入る・緑）／「⚠ 場所が未設定」（赤）／「地図で指定」「Googleマップ」「目印」。
  - カードのボタン：「場所を決める」（地図の画面）・「前の写真と同じ場所」（前のカードに場所があるとき）。区分・至急・コメントはカードごと。区分・コメントは前のカードの値を初めから入れておく。
  - 場所がどうしても分からない写真は、カードの「場所が分からない（本部であとで置く）」で位置なしにできる（確認つき。位置の取り方 none）。
  - 上に「場所が決まっていない写真：n枚」。全部（位置なしを選んだものを含む）決まるまで「送信する」は押せない（押すと未設定のカードへ移動）。
  - 送るとき、**続けて並ぶ写真のうち、場所（緯度経度が同じ）・区分・至急・コメントが同じものを1つの投稿（同じまとまりID）にまとめる**。
- **場所を決める画面**（全画面の重なり）：地図（3-5）。地図をタップした所にピン（もう一度タップで移動、ドラッグも可）。上に「目印から選ぶ」（設定の目印。選ぶと地図が移ってピン）と「Googleマップの座標やリンクを貼る」欄＋「読み取る」（coords.js。短いリンクは resolve）。現在地ボタン。下に大きな「この場所に決める」。決めたら「Googleマップで確認」リンク（新しいタブ、3-6 の URL）も出す。
- **送信中・結果**：進み具合「3 / 12 枚」と棒。終わったら「12枚 送信しました（受付番号 No.12〜No.14）」、送れなかった分は「3枚は送信待ちに入れました。電波が戻ると自動で送ります」。
- **送信待ち**：一覧（サムネ・時刻・理由〔電波・受付停止・合言葉が変わった・混雑〕）、「今すぐ送る」、1件ずつ消す（確認つき）。
- **送った記録**：この端末で送ったもの（新しい順・200件まで。サムネ・受付番号・時刻・区分）。

### 4-3 写真の処理（photo.js・exif.js）

- 写真は**1枚ずつ順番に**処理する（古い機種で落ちないように。前の1枚の画像のメモリを解放してから次へ）。
- **処理が終わった写真は、すぐ下書き（IndexedDB の `draft`）に保存する**。Android ではカメラから戻るとページが読み直されることがあるため。下書きには縮小済みの本体・サムネ（ArrayBuffer）・EXIF・撮影日時・その時点の位置・カードの入力（区分・至急・コメント・場所）を入れ、入力を変えるたびに直す。送信待ちへ移したら下書きから消す。同じファイル（名前・大きさ・更新日時が同じ）が2回入ったら飛ばす。
- 先に元のファイルの先頭 256KB から EXIF を読む（縮小すると消えるため）。
- 読み込みは `createImageBitmap(file)`（向きは自動。使えなければ `<img>` で decode）。読めない（HEIC など）なら「この写真の形式は送れません。カメラの設定で『互換性優先』（iPhone）にするか、別の写真を選んでください」。
- 本体：長辺 2048px の JPEG（品質 0.82）。base64 が 2,700,000 字を超えたら品質 0.7・長辺 1600px で作り直す。
- サムネイル：長辺 320px・品質 0.7。base64 が 45,000 字を超えたら長辺 240px・品質 0.6 で作り直す（シートの1セル5万字の上限）。
- 作った後は canvas の幅を0にし、ImageBitmap は close。

### 4-4 位置（geo.js）

- `acquire({maxMs:8000, goodAcc:30})`：watchPosition で最大8秒、一番精度のよい値。30m 以内なら早めに終える（流用元の acquire を直して使う）。
- `watch(cb)`／`stop()`、`errorKind(e)`（denied・unavailable・timeout・unsupported・failed）と、それぞれの日本語の案内（denied は「位置情報が許可されていません。設定アプリで Safari／Chrome の位置情報を『許可』にしてください」）。
- 町から大きく離れた場所（設定の地図の初期位置から 50km 以上）を選んだら「選んだ場所が町から離れています。合っていますか？」と確認。

### 4-5 送信と送信待ち（outbox.js）

- IndexedDB `spm`（版1）。ストア `draft`（キー id）・`outbox`（キー id）・`history`（キー id）。画像は Blob ではなく **ArrayBuffer** で入れる（古い Safari の不具合を避ける）。
- 送信の流れ：「送信する」で、下書きから**1回のトランザクションで outbox へ移す**（縮小済みの本体・サムネ・項目一式・作った時刻・試した回数・最後の理由・状態）→ 1枚ずつ `upload`（本体とサムネは base64 にして送る）→ 成功したら outbox から消し history に入れる（サムネつき）。
- 送る係は端末の中で1つだけ動かす（`navigator.locks.request('spm-sender', {ifAvailable:true}, …)`。使えなければ localStorage に30秒の「使用中」の印）。送信中のまま3分止まったものは待ちに戻す。
- 失敗の扱い：network・server・busy は自動で3回まで（2秒・5秒・10秒あけて）やり直し、だめなら送信待ちのまま次の写真へ。`closed`・`code` は送信待ちのまま止め、画面に理由を出す（code なら合言葉の画面へ）。`limit` は送信待ちのまま「混み合っています」。`bad` は理由を出してその写真を「送れない」状態に（消すか選ばせる）。
- 再送のきっかけ：送信のとき・`online` のとき・画面に戻ったとき（visibilitychange）・開いている間は60秒ごと。同時に2つの再送が走らないようにする。
- 同じ写真IDで送るので、サーバーに届いていたのに返事だけ失われても二重にならない（dup:true を成功として扱う）。
- 送信待ちがあるときは、どの画面でも上に黄色の帯「⏳ 送信待ち n件（電波が戻ると自動で送ります）」。
- **前の受付の下書き・送信待ち**（作った後に受付中の災害が変わったもの。下書きと送信待ちには作ったときの災害ID・災害名を入れておく）：
  - 下書きは、いまの受付の写真に**混ぜない**（今の画面の一覧・送る対象は、いまの災害IDの下書きだけ）。ホームに黄色の知らせ「前の受付（〇〇）で作りかけの写真が n 枚あります」と、「今の受付で使う」（災害IDをいまのものに付け替えて、元のモードの一覧に入れる）・「消す」（確認つき）。
  - 送信待ちは、自動の再送の対象から外して「前の受付の分」として残す（行き止まりの「災害対策本部へ連絡してください」は出さない）。送信待ちの画面で、その分だけまとめて「今の受付で送る」（付け替えて送る）・「消す」（確認つき）を選べる。黄色の帯の件数にも「（前の受付の分 n件）」と添える。

### 4-6 sw.js・manifest・アイコン

- sw.js：`CACHE_VERSION = 'spm-1.0.0'`。インストール時に投稿ページの本体（index.html・help.html・css の common/post・js の投稿に使うもの・vendor/leaflet・manifest・icons）を保存（`cache:'reload'` で取る）。`config.js` だけはネット優先（3秒で諦めて保存分）。ページの読み込み（navigate）はネット優先→だめなら保存分。同じ場所の静的ファイルは保存分優先。**別のホスト（GAS・地図タイル）と admin.html・admin 用の JS/CSS は保存も横取りもしない（素通し）**。新しい版が入ったら古い保存を消す。
- manifest：name「災害写真マップ」、short_name「写真マップ」、start_url `./index.html`、display standalone、背景白、theme_color `#0b57d0`、アイコン4種。
- tools/make-icons.mjs：濃い青の角丸の地に白いピン（丸＋下向きの三角）と小さなカメラの形を、zlib だけで PNG に描いて `docs/icons/` に書く（192・512・180・32）。
- help.html（投稿する人向け1枚。印刷しても読める）：使い方の流れ、写真の撮り方（このページの「撮る」で撮ると場所が自動で入る）、まとめて送るときの場所の決め方、Googleマップで座標を写す方法（iPhone：地図を長押し→下に出る数字をタップしてコピー／Android：地図を長押し→上の検索欄の数字をコピー。うまくいかなければ「共有」→「リンクをコピー」）、iPhone で写真の位置情報を残す方法（写真を選ぶ画面の「オプション」で「位置情報」をオン。機種・版による）、送信待ちの見方、ホーム画面に追加したときは合言葉の入れ直しが要ること、LINE から開いたとき、困ったときの連絡（「災害対策本部へ」とだけ書く）。

## 5. 管理画面（docs/admin.html・admin.js・admin-map.js・admin-views.js・admin.css・print.css）

PC 向け（タブレットでも崩れない程度に）。左に地図、右に幅 360px のパネル（新着と件数）。幅 900px 未満では右のパネルを下からのシートにする。

### 5-3 地図（admin-map.js）

- 新着が届いたら、その付箋に波紋を2回、右のパネルの新着の先頭に入る。

### 5-4 タイル・一覧・絞り込み（admin-views.js）

### 9-4 動画の投稿
**投稿ページ**
- 写真と同じ所に「🎥 動画」ボタンを足す（現地・まとめての両方）。`<input type="file" accept="video/*">`（スマホでは「撮る／ライブラリから選ぶ」が出る）。現地で選んだときは、そのときの現在地を付ける（写真と同じ）。
- 上限：1本の大きさは設定シートの値（初期 100MB）まで。超えたら「動画が大きすぎます（○MBまで）。短く撮り直してください（30秒くらいがおすすめ）」と出し、下書きに入れない。長さは `<video>` の metadata から読む（読めなくても送れる）。
- サムネイル：`<video>` で 0.5 秒あたりを canvas に描いて JPEG（長辺320px）。描けなければ「▶ 動画」と書いた灰色の絵を canvas で作る。カード・送信待ち・送った記録では ▶ と長さ（例 0:24）を重ねて出す。
- 下書き・送信待ちには、動画のファイルそのもの（ArrayBuffer）を入れる。iPhone の保存の上限に気をつけ、保存できなかったら「端末の空きが足りないため保存できません」と出す。
- **送り方は少しずつ（分けて送る）**：videoStart → videoChunk を何回か → 最後に記録。1回に送る大きさはサーバーが決めた大きさ（初期 2MB。base64 にして送る）。途中で失敗したら、サーバーに聞いた「続きの位置」から送り直す（最初からやり直さない）。電波が切れたら送信待ちのまま、つながったら続きから。進み具合は「動画 12MB 中 4MB」。
- 同じ投稿のまとまりの中で写真と動画をまぜてよい（何枚目・枚数は写真と動画を通しで数える）。

**GAS**
- 「投稿_<災害ID>」に列を足す（見出しで探すので末尾に足す）：「種類」（写真／動画）・「長さ(秒)」・「大きさ(MB)」。今までの行は空なら写真とみなす。
- 設定シート：H9「動画1本の上限（MB）」100、H10「1つの災害の動画の合計の上限（MB）」3000。
- 動画はドライブに**1本のふつうの動画ファイル**として残す（Google ドライブでもそのまま再生できる）。そのために Google ドライブの「再開できるアップロード」（resumable upload）を GAS から使う：`UrlFetchApp` で `https://www.googleapis.com/upload/drive/v3/files?uploadType=resumable&fields=id` に、`Authorization: Bearer ScriptApp.getOAuthToken()`・`X-Upload-Content-Type`・`X-Upload-Content-Length`・名前と親フォルダの JSON を POST → 返ってきた Location（セッションのURL）に、`Content-Range: bytes 開始-終わり/全体` で塊を PUT（塊の大きさは 256KB の倍数。最後だけ端数可）→ 途中は 308（Range 見出しで受け取った所まで）、最後は 200/201 でファイルID。
- API を足す：
  - `videoStart` {token, id, pid, n, of, lat, lng, acc, src, shot, cat, urgent, note, who, org, ua, mime, size, duration, thumb} → 受付・通行証・入力の検査（mime は video/mp4・video/quicktime・video/webm・video/3gpp・video/x-m4v のどれか、size は上限以内、災害の動画の合計の上限）→ すでに同じ id が記録済みなら {ok, dup:true, no} → セッションを作り、CacheService（`spm:vid:<id>`、6時間）にセッションのURL・大きさ・mime・項目一式を置く → {ok, chunkSize, next:0}。同じ id で2回目が来たら、作ってあるセッションの続きの位置を返す。
  - `videoChunk` {token, id, start, data} → セッションが無い（期限切れ）なら {ok:false, error:'restart'}（端末は videoStart からやり直す）。start が続きの位置と違えば、ドライブに「どこまで受け取ったか」を聞いて（`Content-Range: bytes */全体` の PUT）{ok:false, error:'offset', next} を返す。合っていれば PUT し、途中なら {ok, next}、最後なら写真と同じ手順で記録（ロック・受付番号・更新番号・行の追記・サムネイル・災害一覧の数〔写真枚数の欄は「写真・動画の数」として数える〕）して {ok, done:true, id, no}。ファイル名は写真と同じ決まりで拡張子は mime に合わせる（.mp4・.mov・.webm・.3gp・.m4v）。
  - `media`（管理の通行証）{d, id, start, length} → その動画のファイルを `https://www.googleapis.com/drive/v3/files/<ファイルID>?alt=media` に `Range: bytes=start-end` を付けて UrlFetch し、{ok, mime, b64, total} を返す（管理画面が少しずつ取り寄せて再生する。1回 8MB まで）。
  - list・photo などの item に `kind`（photo／video）・`duration`・`sizeMB` を足す。photo は写真だけ（動画の id なら bad）。
- 上限（10分あたり）は動画1本を1件として数える。合計の大きさも記録の「上限」に残す。
- ここで UrlFetchApp と ScriptApp.getOAuthToken を使う。初めて使うときに許可の画面が出ることがある（手引きに書く）。

**管理画面**
- 付箋・束・タイル・一覧・新着で、動画はサムネイルに ▶ と長さを重ねる。一覧の「写真の数」は「写真・動画」。
- 詳細：動画は `<video controls playsinline>` で再生。開いたら `media` で少しずつ（8MB ずつ、同時に2つまで）取り寄せて Blob にし、進み具合（「動画を読み込み中 24MB 中 8MB」）を出す。読み込み中も「Googleドライブで開く」リンク（ドライブに入れる人向け）。
- 出力：CSV・GeoJSON・KML に「種類」「長さ(秒)」を足す。写真のZIP は「動画も入れる（時間がかかります）」のチェックがあるときだけ動画も入れる（初期はオフ）。
- 印刷：動画はサムネイルに「▶ 動画（0:24）」と書いて載せる。
